# Admin API errors

Admin API errors use `{ "error": { "code", "message", "request_id", "details" } }`. Request IDs are generated by the backend and returned as `X-Request-ID`. Authentication errors do not say whether an account exists.

| Code | Meaning |
| --- | --- |
| `ADMIN_INVALID_CREDENTIALS` | The supplied credentials cannot be used. |
| `ADMIN_AUTH_REQUIRED` | A valid, active admin session is required. |
| `ADMIN_PERMISSION_DENIED` | The admin role cannot perform this action. |
| `ADMIN_RATE_LIMITED` | The attempt limit was reached. |
| `ADMIN_AUTH_UNAVAILABLE` | Admin authentication cannot safely proceed, such as when its encryption configuration or rate-limit cache is unavailable. |
| `ADMIN_REQUEST_INVALID` | The request could not be processed. |
| `ADMIN_REAUTH_REQUIRED` | A sensitive control requires recent password and TOTP re-authentication. |
| `ADMIN_FLAG_INVALID` | A control change is missing a valid value, reason or exact typed confirmation. |
| `ADMIN_FLAG_NOT_FOUND` | The requested control is not implemented. |

The existing rider API retains its existing error envelope. Network and proxy failures can occur before a request reaches the admin API and have a simpler local error response.
